# Notion のページの編集

## 編集してよい範囲（最優先）

- **編集してよいのは、ユーザーが URL か名前で指定したページだけ。** ほかのページ（親・子・同じ階層・リンク先・データベースの行）は、編集・移動・削除・複製・コメントをしない。
- ほかのページに手を入れる必要が出たら、作業を止め、**どのページに・何をするか・なぜか**を書いて、明示的な許可を求める。許可は、そのページ・その操作に限る（別のページや別の操作には引き継がない）。
- 指定されたページの下に新しいページを作るのも、ページを増やす操作なので、許可を得てから行う。
- 読むのも、作業に要るページだけにする。検索や `fetch` でほかのページの中身を見て、本文に引用・要約するときは、そのことを伝える。
- 次の書き方は、ほかのページを動かしたり消したりするので使わない。
  - **`<page url="...">`**: 既存のページの URL を入れると、そのページがこのページの子に**移動**する。ほかのページに触れるときは `<mention-page url="...">` を使う。
  - **`<database url="...">`**: 同じく既存のデータベースが移動する。触れるだけなら `<mention-database>`。
  - **`replace_content` で既存の `<page>`・`<database>` の行を消す**: 子のページやデータベースが消える。

## 手順

1. **読む**: 編集の前に必ず `notion-fetch` で対象のページを読む。初めて書くときは、書式の仕様（`notion://docs/enhanced-markdown-spec`）も `notion-fetch` で読む（推測で書かない）。
2. **決める**: 何を足し・直し・消すかを決める。ユーザーが書いた文を大きく消す・書き換えるときは、先に確認する。
3. **最小の操作で書く**
   - 一部を直す: `update_content`（見つける文字列は、ページの中で 1 か所に決まる短いもの）
   - 先頭・末尾に足す: `insert_content`
   - 全体の置き換え: `replace_content` は、空のページか、ユーザーが全体の作り直しを頼んだときだけ。子のページやデータベースの行は、読んだときのタグのまま残す。
   - 「子のページが消える」というエラーが出たら、その一覧をユーザーに見せて確認する。`allow_deleting_content: true` は確認なしに使わない。
4. **確かめる**: 構造を変えた編集のあとは、もう一度 `notion-fetch` して、見出し・入れ子・表・折りたたみが意図どおりかを見る。`warnings` が返ったら報告する。非同期の結果（`async_task`）が返ったら、完了を待ってから確かめる。
5. **報告する**: どのページの、どこを、どう変えたかを短く伝える。ほかのページに触れていないことも書く。

## 書き方（簡潔に）

- **結論から書く。** 冒頭に 1〜3 行の要点を置く（コールアウトにしてもよい）。見出しは「何が分かるか」が分かる短い名詞句か文にする。
- **最初に見える部分は要点だけにし、詳細は折りたたむ。** 根拠・手順・長い表・補足は、トグル（`<details><summary>…</summary>` の中身をタブで字下げ）か、トグル見出し（`## 見出し {toggle="true"}`）に入れる。
- **箇条書きを使う。** 並列の事柄・手順・理由は文でつながずに箇条書きにする。各項目の頭に太字の短い見出しを置くと拾い読みしやすい。入れ子は 2 段まで。
- **比べるものは表にする。** 表のセルにはリッチテキストしか入らない（見出し・箇条書き・画像は不可。HTML タグも不可）。
- **必要に応じて強調。** 色（`<span color="red">`、`{color="blue_bg"}`）と太字は、読み飛ばされたくない結論など重要な項目に利用する。
- **横に並べると読みやすいもの**（前と後、2 つの案）は `<columns>` で並べる。
- 日付・人・ほかのページは、文字で書かずにメンション（`<mention-date>`・`<mention-user>`・`<mention-page>`）にする。ただし、ほかのページへのメンションは、触れてよいかが曖昧なら使わない。
- 書式の記号（`* ~ \` $ [ ] < > { } | ^`）を文字として書くときはバックスラッシュで逃がす。コードブロックの中は逃がさない。

## 図と模式図

- **仕組み・流れ・前後の違い・関係**を文章で説明しそうなところは、図にできないかを先に考える。
- **Mermaid のコードブロック**（` ```mermaid `）は Notion で図として表示される。流れ図（`flowchart LR`）、手順（`sequenceDiagram`）、時系列（`gantt`）、状態（`stateDiagram-v2`）に向く。
  - かっこなどの記号を含む文字は、ノードの名前を二重引用符で囲む（`A["SBML (不完全)"]`）。改行は `<br>`。`\(` は使わない。
  - ノードは 10 個程度までにし、ノードの文字は短い名前にする。説明は図の下に 1〜2 行で書く。
- **値のグラフや、Mermaid では描けない図**は、画像にしてアップロードする（`notion-create-file-upload` で上げ、返る `suggested_markdown` を本文に入れる）。外部の画像は URL で `![説明](URL)` と置ける。
- 図の下に「何を表す図か」と「結論」を 1 行書く。

## Notion の書式の要点

| 用途 | 書き方 |
| --- | --- |
| 折りたたみ | `<details>` と `<summary>…</summary>`、中身はタブで字下げ |
| 折りたたみ見出し | `## 見出し {toggle="true"}`、中身はタブで字下げ |
| コールアウト | `<callout icon="💡" color="gray_bg">`、中身はタブで字下げ |
| 表 | `<table header-row="true">` と `<tr>`・`<td>`（列の色は `<colgroup>`） |
| 段組み | `<columns>` と `<column>` |
| 目次 | `<table_of_contents/>` |
| 色 | 文字色 `gray brown orange yellow green blue purple pink red`、背景は `_bg` を付ける |

- 字下げは**タブ**で行う（空白では入れ子にならない）。
- 空行は無視される。どうしても空けたいときだけ `<empty-block/>` を独立した行に置く。
- 引用の中では改行の代わりに `<br>` を使う（改行すると別の引用に分かれる）。
