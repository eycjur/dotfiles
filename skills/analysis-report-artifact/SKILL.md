# 分析レポートの Artifact

書き始める前に artifact-design スキルを読み、グラフを作るなら dataviz スキル、模式図を描くなら artifact-diagramming スキルも読む。
最初に、読者と、読者がこのレポートで判断したいことを決める。節・図・表は、その判断に要るかで取捨する。

## 構成

### 1 つの Artifact にタブを足していく

- 同じテーマのレポートは 1 つの Artifact にまとめ、実験・分析の単位（実行・版・調査）ごとにタブを分ける。ユーザーの希望がない限り、別の Artifact を作らない。
- 新しいタブは関連するタブの直後に置く（「結果」の次に「結果を受けた改善」）。仕組みの説明のような横断的なタブは最後。
- タブ名は短い名詞句。ユーザーが名前を指定したら、タブのボタンと見出し（h1）の両方を変え、ほかのタブの本文にある参照も探して直す。Artifact の `<title>` は変えない。
- ほかのタブの内容に触れるときは、タブ名を「」で書き、クリックでそのタブ（できれば該当の節）に移れるリンクにする。

### タブは上に固定する

- タブの帯は `position: sticky; top: env(safe-area-inset-top, 0px)` で上に固定する。その下に止めたい補助のバー（図の指標の切り替えなど）は、タブの実際の高さを JS で測った `--tabs-h` の分だけ下げて止める（タブが折り返して 2 段になっても重ならない）。

```html

  <button type="button" role="tab" id="t-a" aria-controls="tab-a" aria-selected="true">結果</button>
  <button type="button" role="tab" id="t-b" aria-controls="tab-b" aria-selected="false">改善</button>
</nav>
<div class="wrap" id="tab-a" role="tabpanel" aria-labelledby="t-a">…</div>
<div class="wrap" id="tab-b" role="tabpanel" aria-labelledby="t-b" hidden>…</div>
<script>
for (const b of document.querySelectorAll(".tabs button")) {
  b.addEventListener("click", () => {
    for (const x of document.querySelectorAll(".tabs button")) {
      const on = x === b;
      x.setAttribute("aria-selected", on);
      document.getElementById(x.getAttribute("aria-controls")).hidden = !on;
    }
  });
}
(() => {
  const tabs = document.querySelector(".tabs");
```

### 1 タブの節の型

| 節 | 中身 |
| --- | --- |
| ヘッダ | 小さな見出し（実行の ID・対象・状態（完了・途中経過・停止）と日時）、h1、リード文（このタブで何を調べたかを 1〜2 文）、短い札（対象・期間・件数など） |
| 要点 | 3〜5 項目を重要な順に。各項目は**太字の結論 1 文**＋根拠の数字。ここだけ読めば判断できるようにする。判断を求めるレポートでは、推奨する行動・最大のリスク・確信度も入れる。予想や前の結果と違ったことは、上の方に置く。要点の項目ごとに折りたたみ（`<details>`）を付けてよい。項目の文は短く保ち、根拠の内訳・計算・例はその中に入れる |
| 条件・変更点 | 何をどう回したか。前の版との違いは「項目 / 前 / 後 / ねらい」の表にし、下に「変えていないもの」を書く |
| 結果 | 図が主役。図の下に説明。細かい数字の表は折りたたみ（`<details>`）の中 |
| 分析 | 1 項目 1 主張の一覧。左に状態の札（下の表）、右に太字の主張＋根拠 |
| 考察 | ユーザーと決めた観点を、毎回同じ小見出しで並べる |
| 分かっていないこと | 確かめていないこと・確度の低い結論と、その理由。追加で何が分かれば判断の確度が一番上がるかを優先順に |
| 次にやるなら | 次の作業・その見込み・残っている問題 |
| 方法と出典 | 使ったデータ・計算の仕方・仮定・用語の定義。折りたたみに入れて最後に置く |

- 節は左に見出しの列、右に本文の 2 段にし、狭い画面では 1 段にする。
- 長い補足（内訳・例・理由の詳細）は `<details><summary>` に入れ、本文の流れを止めない。
- 情報は削らずに階層化する。最初に見える部分は判断に要る情報だけにし、根拠・計算・詳しいデータは折りたたみ・タブ・ツールチップに移す（「簡潔に」と言われても、内容を消すのではなく下の階層へ移す）。
- 分かりやすくなるなら、動的な部分を入れる。たとえば、図の指標や条件の切り替え（タブの下に固定したバーのボタン）、候補や条件の表示・非表示、表の並べ替え、ホバーやクリックで根拠・数値を出す、概要から詳細への掘り下げ。同じ形の図を何枚も並べるより、切り替えで 1 枚にまとめる方が読みやすいことが多い。動かすこと自体を目的にせず、動かさなくても最初の表示で結論が読めるようにする。

## 文章

- **結論から書く。** 節も項目も、最初の文で言い切る。結論の文には、良いか悪いかの向きと大きさを入れる（「差が大きくなった」ではなく「ノイズありで弱くなり、差が前の約 2 倍になった」）。
- **端的に書く。** 1 項目は 1〜2 文。前置き・経緯・言い換えの繰り返しを書かない。説明が長くなりそうなら、図や表にできないかを先に考え、本文には要点だけを残して残りは折りたたみ（`<details>`）に入れる。
- 平易に書く。専門用語・指標名は初出の際にツールチップ（`<button type="button" class="help" data-tip="表示文字列" aria-label="ラベル" aria-expanded="false">?</button>`。CSSで.help:hover::afterを制御し、タップでも開くよう click で aria-expanded を切り替える）を付与するなど説明を記載し、以降は同じ言葉を使う。
- **比べるものは、読み手に分かる呼び名で呼ぶ。** 内部の番号（実験の番号・job の ID・ディレクトリ名）ではなく、「以前・今回」「前の版・新しい版」のように呼び、タブの中で統一する。番号や ID は、初出のツールチップと「方法と出典」に置く。
- 箇条書きを積極的に使う。並列の事柄・手順・理由・条件は、文章でつながずに箇条書きにする。各項目の頭に太字の短い見出しを置くと、拾い読みしやすい。入れ子は 2 段まで。
- 本文でも、必要に応じて色で強調する。読み飛ばされたくない数字・結論・注意点に、図や表と同じ意味の色を付ける（問題・悪化は暖色、改善・推奨はアクセント色。`<b class="warn">` のようにクラスで指定する）。要点だけでなく、分析・考察の結論にも使う。差がない・判断を変えない結果には付けない。1 段落に 1〜2 か所までにし、色だけでなく太字も添えて、色が見えなくても伝わるようにする。
- **主張には数字を添える**（値・件数・± 標準誤差・p・勝ち／引き分け／負け）。「大きい」「多い」で終えない。
- **値には、可能なら誤差の範囲を付ける。** 平均・差・割合には ± 標準誤差（または 95% 信頼区間）を、本文・表・図（誤差の線）のどれでも付ける。どちらの範囲かを書く。1 回だけの値などで付けられないときは、その旨を書く。
- 平均や件数の主張には、代表的な具体例（対象の名前・実際の値・記録の抜粋）を付けると伝わりやすい。本文には書かず、ホバーで出す（ツールチップ、または図の点や行の `data-tip`）。
- **数字には比べる基準と意味を添える。**「値 → 比べる基準（前の版・平均・目標）→ それが何を意味するか」の順に書き、裸の数字で終えない。
- **事実と解釈を分ける。** 記録から数えたものと推測を、状態の札で区別する。推測には確かめ方を添える。
- 主要な結論には、反証や別の説明と、「何が分かれば結論が変わるか」を添える。情報どうしが食い違うときは、片方を選ばず食い違いを示す。
- キーワードなどで機械的に数えた指標は「目安」と書く。
- 前のタブの結論と食い違う結果が出たら、どのタブかを示して並べる（黙って書き換えない）。
- 何をしたかをメインで記載し、何をしなかったのかや過去のバージョンからの変更点はユーザーの指示がない限り記載しなくて良い。

| 状態の札 | 使う場面 |
| --- | --- |
| 記録から | 記録・ログから数えた事実 |
| 計算から | 記録から計算・推定した値（推定の仮定を添える） |
| 解釈（仮説） | 記録からの推測。確かめ方を添える |
| 支持 / 一部 / 差なし | 検証したい主張に対する判定 |
| 比べられない / 設計の問題 | 結果を読むうえで注意が要る |
| 不明 | 情報が足りず判断できない |

## 数字と比べ方

- 数字は元の出力からスクリプトで出し直す。前の版の数字を書き写さない。
- 新しい集計のやり方は、既存の集計と同じ値が出るかで確かめてから使う。
- **平均の取り方を書く**（欠けた値・失敗をどう扱ったか）。
- **同じ対象どうしの比較**は、差の平均 ± 標準誤差、対応のある検定の p、勝ち・引き分け・負けを書く。対象ごとの結果が手元にないときは「平均どうしの比較で、対応のある検定はしていない」と書く。
- **揺れの物差しを持つ。** 標準誤差などを元に、有意差があるのか、偶然の可能性があるのかを記載する。物差しは出どころ（どの比較の、どの範囲の値か）を書き、範囲の違う比較にそのまま当てはめない。
- **集計の単位に気をつける。** 要素の数をそのまま足すと、大きい対象や外れ値の 1 件に引っぱられる。対象ごとに割合を出してから平均し、どちらで数えたかを書く。
- **平均と中央値が離れるとき**（費用・時間・回数）は、両方と最大、偏り（上位何 % で何 %）を示す。
- **比べる範囲をそろえる。** 片方で欠けた・除いた対象は、もう片方からも除き、除いたものを書く。
- 比べる 2 つの間に違いが複数あるときは、違いを表にし、「差のすべてがこの変更の効果とは限らない」と書く。
- **相関と因果を区別する。** 対象が自分で選ばれた群どうしの比較（ある機能を使った対象と使わなかった対象など）は、選ばれ方の偏り（難しい対象ほど使われる、など）で差が出うるので、「〜と一緒に起きている」と書き、「〜のせいで」と書かない。因果を言えるのは、条件だけを変えて同じ対象で比べたときに限る。
- 推定に使う仮定（単価・換算係数など）は、タブどうしで同じ出し方にそろえる。出し方を変えたら、前のタブの値との違いを書く。
- 数字の範囲を本文・図・表で合わせる（ある条件だけで数えた割合と、全体の割合を比べない）。

## グラフ（データの値を描く図）

### 見せたいことと形

グラフは、データがあるから作るのではなく、読者の問いに答えるために作る。正確な値を比べたいなら表にする。

| 見せたいこと | 形 |
| --- | --- |
| 条件ごとの値をいくつかの版・手法で並べる | 点＋± 標準誤差の線。グループごとに小さな図を横に並べ、縦軸をそろえる |
| 前の版と今回の比較（条件ごと） | 行ごとのダンベル。比べる元を灰、今回をアクセント色の点にし、2 点を細い線で結ぶ。右端に件数 |
| 同じものの 2 つの状態 | ダンベル（2 点を線で結ぶ）、または塗りと白抜きの点 |
| 1 回ごとの揺れ・ばらつき | 1 件 1 点のドットプロット（同じ値は少しずらす）。平均や標準偏差では見えない形が見える |
| 回数の分布 | 棒（ヒストグラム）。上限を点線で |
| 内訳・割合 | 横の積み上げ棒に直接ラベル、または 100% の帯 |
| 同じ量の内訳を前後で比べる | 区分ごとに前と今回の 2 本の横棒を並べる（同じ単位）。棒の端に値 |
| 2 つの量の割合 | 同じ単位（%）にそろえた 2 本の横棒を並べる |
| 区分ごとの量 | 縦棒。件数を下に |
| 時間とともに変わる量 | 折れ線 |
| 2 つの量の関係 | 散布図 |
| 多数の候補を複数の観点で比べる | 表（観点を列に）か、ヒートマップ |


### レイアウト

- 行の並びは表と同じ順にそろえ、グループの間に少し隙間を空ける。
- 0〜1 の指標は軸を 0〜1 に固定する。差を大きく見せるために軸を切り詰めない（差の図は 0 の線を濃くする）。
- 件数や値は、マークの近く（棒の端・行の右端）に直接書く。凡例は図の下にまとめる。
- 1 件 1 点の図では、同じ値の点を上下に少しずらして重なりを見せる。同じ値が多すぎて積むと高くなるとき（差が 0 の対象など）は、点の代わりに件数の札（「同じ 46」）を置く。札が点と重ならないよう、軸の下などに置く。
- 図の見出しは変数名（「売上の推移」）ではなく結論（「売上は Q2 以降回復しているが、前年比ではまだ 12% 低い」）にする。説明文は図の下に書き、図の中に長い文を入れない。

### 作り方

- **見せ方が 1 通りで足りる図は静的な SVG。** スクリプトで出力から値を読み、SVG の文字列を作って HTML に差し込む（原稿の `@@名前@@` を置き換える）。色・文字は CSS のトークンとクラスで指定し（`style="fill:var(--accent)"`）、16 進の色を直接書かない。点や棒に `data-tip` を付け、ホバーとタップで「条件・系列: 値 ± 誤差（件数）」を出す。SVG の `<title>` は使わない（Artifact ではホバーでも出ないことがあり、タップでは出ない）。代わりに、ページに浮かぶツールチップを 1 つ置き、`svg [data-tip]` の `pointerenter`・`focus`・`click` で要素の下に出す（`position: fixed`）。図の中に補足（具体例など）を置くときも、同じ仕組みの小さなボタン（`<g tabindex="0" role="button" data-tip="…">`）にする。
- **情報量が多く、読者が動かして見たくなりそうな図は、Plotly で描く方法もある。** 点や系列が多い図、時系列、散布図などで、ホバーで値を見る・拡大や移動をする・凡例のクリックで系列を出し入れする・ボタンで切り替える、といった操作が役に立つときに使う。cdnjs から版を固定して読み込む。折れ線・散布図・棒なら軽い版（`plotly-basic.min.js`、約 1.2 MB）、箱ひげ・ヒストグラム・ヒートマップも使うなら `plotly-cartesian.min.js`（約 1.5 MB）。
  - データは JSON としてページに埋め込む（外部からは読み込めない）。
  - 色と文字はページのトークンを `getComputedStyle` で読んで渡し、明暗のテーマが変わったら描き直す。背景は透明にしてページの地に合わせる。
  - 最初の表示で結論が読めるようにする（初期の範囲・表示する系列を決めておく）。ツールバーは要るボタンだけにする。

```html
<script src="https://cdnjs.cloudflare.com/ajax/libs/plotly.js/4.1.2/plotly-basic.min.js"></script>
<div id="fig-x" style="height:360px"></div>
<script>
const DATA = /* スクリプトが埋め込む JSON */ {"x": [5, 20], "before": [0.86, 0.91], "after": [0.80, 0.88]};
function drawX() {
  const css = getComputedStyle(document.documentElement), v = n => css.getPropertyValue(n).trim();
  Plotly.react("fig-x", [
    {x: DATA.x, y: DATA.before, name: "前", mode: "lines+markers", line: {color: v("--ink-2")}},
    {x: DATA.x, y: DATA.after, name: "今回", mode: "lines+markers", line: {color: v("--accent")}},
  ], {
    paper_bgcolor: "rgba(0,0,0,0)", plot_bgcolor: "rgba(0,0,0,0)",
    font: {color: v("--ink"), family: v("--f-body")},
    xaxis: {gridcolor: v("--rule")}, yaxis: {gridcolor: v("--rule"), range: [0, 1]},
    margin: {t: 10, r: 10, b: 40, l: 50}, legend: {orientation: "h"},
  }, {responsive: true, displaylogo: false, modeBarButtonsToRemove: ["lasso2d", "select2d"]});
}
drawX();
matchMedia("(prefers-color-scheme: dark)").addEventListener("change", drawX);
new MutationObserver(drawX).observe(document.documentElement, {attributes: true, attributeFilter: ["data-theme"]});
</script>
```

- 隠れたタブの中の Plotly の図は幅が 0 で描かれるので、タブを開いたときに `Plotly.Plots.resize` を呼ぶ。

### 説明

- 図の下に 1〜2 文で、「何を見る図か」（点・線・色の読み方）と「結論」を書く。
- 平均の取り方と、誤差の線の意味（± 標準誤差など）を書く。
- 比べる相手の値の出どころを書く。

### 確認

- 公開前に一度描画して見る。ブラウザが使えなければ、座標でラベルの重なりを確かめる（幅の狭い区分のラベル、長い名前、凡例）。重なるときはラベルを上下 2 段に互い違いに置く。
- 図・本文・表の数字が一致しているかを見る。

## 模式図（仕組み・流れ・違いを描くイラスト）

描く前に artifact-diagramming スキルを読む。

**模式図は積極的に入れる。** 仕組み・流れ・前後の違い（処理の流れ、役割の分担、ある仕組みの前と後、期待と実際の違い）を文章で説明しているところは、模式図にできないかを先に考え、できるなら図を主にして文章は補足にする。変更点・原因・誤りの型のように、文章だと何段落にもなる説明ほど図が効く。値はグラフで描く。

### 描き方

- 座標を決めた静的な SVG で描き、色と文字はグラフと同じトークンとクラスで指定する。
- 比べるものは上下に並べ、上を前（期待）、下を後（実際）にする。左右の位置をそろえ、同じものは同じ位置に置く。
- 箱の大きさと形をそろえ、箱の中の文字は短い名前にする。役割で見た目を分ける（地の箱・強調の箱・注意の箱・省いたものは点線の箱）。
- 変わった部分・問題の部分だけに色を付ける（問題は注意の色、良くなった部分はアクセント色）。色の付いた括弧と短い注記で「ここが何か」を指す。
- 矢印の向きで主従を表す（呼ぶ側 → 呼ばれる側）。矢印の `marker` の id は図ごとに変える（同じページに複数あるため）。
- 各パネルに見出しと、1 行の要点を付ける。
- 図の下に、何の例か（実際のどの対象か）を書く。

### 確認

- 箱・矢印・文字が重ならないか、座標で確かめる。SVG は XML として読めるかを確かめる。
- 模式図の中の言葉が、本文の言葉と同じか（同じものを別の名前で呼ばない）。

## 色（グラフ・模式図・表・本文で共通）

- 色には意味を割り当て、レポート全体で固定する（例: 注意・問題＝暖色、比べる元・その他＝灰、今回の主役＝アクセント色、対になる 2 状態＝対比の 2 色）。同じ系列は全タブで同じ色にする。
- 1 つの図で区別に使う色は 2 色までを目安にする。3 つ以上は灰を混ぜるか、図を分ける。
- 配色は dataviz スキルの検証スクリプトで確かめる。
- 既存のレポートに足すときは、既存の色のトークンとクラスを使う。足りないクラスだけを 1〜2 行足し、全体のトークンは変えない。

## 表

### いつ表にするか

- 図で傾向を見せ、正確な値は表に置く。図の下の「細かい数字」は折りたたみ（`<details>`）に入れる。
- 1 件ずつ並べた箇条書き（失敗やエラーの一覧など）は、理由ごとの件数の表にまとめる。列は「理由 / 件数 / どこで / 比べる相手の値」、最後に合計の行。
- 候補を比べる表では、どの候補でも同じ項目ではなく、判断を分ける差のある項目を強調する。総合点や順位を出すときは、順位を決めた主な要因を併記する。

### 概要を先に、詳細はたたむ

最初は概要の表（合計・区分ごとの行・判断に要る列）だけを見せ、詳細は開いたときに出す。たたみ方は詳細の形で選ぶ。

| 詳細の形 | たたみ方 |
| --- | --- |
| 概要の行の内訳（同じ列のまま行が増える。区分 → その中の対象など） | 表の中でたたむ。概要の行をクリックすると、その下に内訳の行が開く。列がそろったまま見比べられる |
| 列や単位が違う別の表、または行の多い一覧 | 概要の表の下に `<details>` で置く。`<summary>` には中身（「対象ごとの値（192 行）」など）を書く |

- 表の中でたたむときは、グループごとに `<tbody>` を分け、概要の行に開閉のボタンを置く（`<details>` は表の行をまたげない）。
- 開く前でも結論が読めるように、概要の行に合計や平均を出しておく。

```html
<tbody class="grp">
  <tr class="sum"><th><button type="button" aria-expanded="false">▸ 区分 A</button></th><td>0.82</td><td>40</td></tr>
  <tr class="sub" hidden><td>対象 1</td><td>0.90</td><td>10</td></tr>
  <tr class="sub" hidden><td>対象 2</td><td>0.75</td><td>10</td></tr>
</tbody>
<script>
for (const b of document.querySelectorAll("tr.sum button")) {
  b.addEventListener("click", () => {
    const open = b.getAttribute("aria-expanded") !== "true";
    b.setAttribute("aria-expanded", open);
    b.textContent = (open ? "▾" : "▸") + b.textContent.slice(1);
    for (const r of b.closest("tbody").querySelectorAll("tr.sub")) r.hidden = !open;
  });
}
</script>
```

### 作り方

- グループ（合計・1 件あたり・内訳・区分別など）は、表の中の見出し行で区切る。表を分けすぎない。
- 長い文の入るセル（変更点・どこで）だけ折り返しを許す。
- 1 つのセルに 2 つの値を並べる（「今回 / 前」）ときは、見出しか注記で順番を書く。
- 強調は少なく使う。一番伝えたい値（最も変わった行・合計）を 1 種類の強調で、注意すべき値を警告の色で。
- 比べられない行（条件が違うものなど）は、表に入れても比は「—」にし、注記で理由を書く。

### 表の下の注記

- 平均の取り方（欠けた値・失敗をどう扱ったか）。
- 数字の出どころ（どの記録から足したか）と、推定を含む値。推定なら合計と少しずれることも書く。
- 比べる範囲（そろえた対象、除いたもの）。

## 更新の手順

1. **正本は Artifact。** 原稿・集計スクリプト・図のスクリプトは作業用の場所に置き、消える前提で動く。Artifact の URL と、版ごとの変更はメモリに残す。
2. **読む。** 別のセッションで公開した Artifact は `action: "read"` で読み、保存された HTML を全行読む。図の行が長いので、行の長さを数えて数万字ずつに区切って読む。
3. **取り出す。** 保存された HTML の公開時の枠を除き、`<title>` から `</body></html>` の前までを原稿にする。
4. **直す。** スクリプトの文字列置換で直し、置換の前に置き換える箇所がちょうど 1 つかを確かめる（`assert s.count(old) == 1`）。
   - タブを足す: ボタンを関連するボタンの後ろに、パネルを関連するパネルの後ろに入れ、ボタンとパネルの数が同じかを数える。
   - タブを直す: パネルの開始から次のパネルの開始の前までを、新しい原稿で丸ごと置き換える。
   - タブを作り直すスクリプトは、直す前の原稿のコピーから毎回組み立てる。何度回しても同じ結果になり、手直しのたびに回し直せる。
   - 図: 印を SVG で置き換え、置き換え残しがないかを確かめる。
5. **確かめる。** タグの整合、図の XML、タブとパネルの数、数字の一致、途中経過の表記の残り。
   読み手の目でも見る: 最初の数秒で結論が分かるか、重要な数字に比べる基準と意味があるか、事実と推測が分かれているか、分かっていないことを隠していないか、要らない図や飾りがないか。
6. **公開する。** 同じセッションで公開したものは同じファイルパスで、別のセッションのものは `url` を指定して公開する。`label` に何を変えたかを短く書く。
7. **記録する。** メモリに版と変更を書き足す。

### 訂正と報告

- 修正の依頼では、変えるものと保つものを確かめ、保つ部分（数字・本文・ほかのタブ）には触らない。依頼が「もっと良く」のように曖昧なら、何を変えるかを決めてから直す。
- 公開後に誤りに気づいたら直して公開し、報告で「何が、どう違っていたか」をはっきり書く。前のタブの誤りも、気づいたら直す。
- 原稿を書き換えるスクリプトは、読み込んだだけでは原稿を書き換えない作りにする（`if __name__ == "__main__":`）。値だけを使うつもりで読み込んで、手で足した節を上書きしてしまうことがある。上書きしてしまったら、公開中の版を `action: "read"` で取り直して原稿にする。
