# App Store Connect の項目一覧と決め方

App Store Connect の左メニュー順。各項目の「決め方」に従い、リポジトリと既存 metadata から入力値を決める。
貼る文言の全文は各アプリの `marketing/app-store-metadata.md`（本ファイルは定義と判断、metadata は本文）。

## 左メニューの構成

| メニュー | 変更の扱い | 主な項目 |
|----------|-----------|----------|
| iOS App > バージョン（例 1.0） | バージョンごと。審査対象 | スクリーンショット、プロモーションテキスト、概要、キーワード、URL、著作権、ビルド、App Review情報、このバージョンの最新情報（2回目以降） |
| App情報 | 全バージョン共通。変更は次バージョンで反映 | 名前、サブタイトル、一般情報、年齢制限、暗号化、規制と許可 |
| Appのプライバシー | 全バージョン共通 | プライバシーポリシーURL、データ収集の申告 |
| アプリのアクセシビリティ | 全バージョン共通 | 対応機能の申告 |
| 価格および配信状況 | 全バージョン共通 | 価格、配信国、Mac/Vision Pro 配信 |
| TestFlight | ビルドごと | 内部テスター、テスト情報 |

metadata ファイルの並びは、Connect で最初に開く「バージョン情報」を先頭にし、App Review → App情報 → Appのプライバシー → アクセシビリティ → 価格および配信状況 → 公開後、の順にする（価格は左メニューの一番下）。

## バージョン情報（審査対象）

| 項目 | 決め方 |
|------|--------|
| プレビューとスクリーンショット | 必須サイズ枠に既存または再出力した枚数を置く。見た目変更があったスライドだけ撮り直す。価格表現を入れない。App プレビュー動画は、用意がなければ使わない |
| プロモーションテキスト（170字） | 価値を1つに絞る。対象が明確なら先に言い切る。審査なしで差し替え可能なので季節・訴求に合わせて更新してよい。既存 metadata があればそれを土台に差分更新 |
| 概要（4000字） | README「機能」や同等の説明と整合させる。新機能はユーザー向けの節に1行追加。API名などユーザー向けでない語は書かない。価格に触れるならここだけ |
| キーワード（100字） | 名前・サブタイトルの語は入れない。新機能で検索されそうな語があれば、弱い語と入れ替える。カンマ区切りで100字以内 |
| サポートURL | 公開中のサポートページURL。Pages / README / 既存 metadata から特定。ハイフン／アンダースコアの取り違えに注意 |
| マーケティングURL | ランディングページがなければ空欄 |
| 著作権 | 既存 metadata またはユーザー指定。年が変わったら範囲表記に更新。勝手に本名や別アカウント名を入れない |
| ルーティングAppカバレッジファイル | 経路案内アプリでなければ「なし」 |
| このバージョンの最新情報（4000字） | 初回提出では項目なし／不要なことが多い。2回目以降は必須。git log と README からユーザーに見える変更を「・」箇条書きで3〜8行。不具合修正は「〜を修正しました」。内部変更は書かない |
| ビルド | アップロード済みで `CFBundleVersion` が前回より大きいビルドを選ぶ |
| バージョン | `MARKETING_VERSION`（または同等）と一致させる |
| 配信方法（バージョンのリリース） | 公開前に Pages の `main` を揃える必要があるなら「手動でこのバージョンをリリース」。急がない・同期不要なら「自動」でもよい |
| 段階的リリース | 配信規模が小さく不要なら使わない |
| リセット評価 | 大幅刷新時のみ検討。通常は使わない |

## App Reviewに関する情報（バージョン情報の下部）

| 項目 | 決め方 |
|------|--------|
| サインインが必要 | アカウント機能がなければオフ。追加したらオンにし、デモ用認証情報をメモに書く |
| 連絡先（氏名・電話・メール） | Connect に登録済みのものを使う。公開されない。前回と同じでよい。こちらでは新規に推測して埋めない |
| メモ | 日本語でよい。次の7項目構成。プレースホルダ記法は使わず実際の値を書く。再提出時は冒頭に「Update since the last review:」で対応内容とバイナリ変更の有無 |
| 添付ファイル | 録画をリンクでなく添付にしてもよい。任意 |

### 審査メモの7項目

1. **Screen recording**: 実機の画面録画へのリンク。主要フローを起動から通す。録画できない画面は補足スクショ。リンクはユーザーに確認する
2. **Devices and OS used for testing**: 実機の機種名と OS バージョン
3. **App overview**: 対象ユーザー、無料／有料、オフライン可否、データの保存場所
4. **Setup and access**: ログイン要否、権限の説明（必須／任意とその範囲）、データなしでも開ける画面の有無
5. **External services**: 利用API・送信データの範囲、解析・広告・決済の有無
6. **Regional differences**: 対応言語・配信地域
7. **Regulated industries / third-party content**: 第三者コンテンツの帰属、アイコンの出所、規制業種の該当有無

## App情報

| 項目 | 決め方 |
|------|--------|
| 名前（30字） | 既存の App Store 名 / `CFBundleDisplayName` / 既存 metadata。むやみに変えない（変更は次バージョン反映） |
| サブタイトル（30字） | 検索で効かせたい語を含める。名前と重複させすぎない。既存があれば差分更新 |
| バンドルID | `PRODUCT_BUNDLE_IDENTIFIER`。固定。変えない |
| SKU | 初回作成時の値。固定。変えない |
| Apple ID | App Store Connect の数字ID。アップデート確認コードと一致させる。リポジトリまたは Connect から確認 |
| コンテンツ配信権 | 第三者コンテンツ（天気・地図・他社データ等）を表示するなら「はい（必要な権利を保有）」。帰属表示をアプリ／ポリシーに置く。外部データを増やしても「はい」のまま帰属を追加 |
| 使用許諾契約 | 独自 EULA がなければ Apple の標準使用許諾契約 |
| プライマリ言語 | アプリの主言語（ローカライズ方針と一致） |
| カテゴリ | アプリ実態に合わせる。既存があれば据え置き |
| 年齢制限指定 | 7ステップをアプリ内容から回答し、metadata に再現可能に書く。外部ブラウザで開くリンクはアプリ内の「無制限のWebアクセス」とは限らない。記録・達成表示をコンテスト／ギャンブルに安易に当てない。年齢適合性URLはなければ空欄。上書きは該当なしなら「該当なし」 |
| アプリの暗号化に関する書類 | `ITSAppUsesNonExemptEncryption: false` で OS 標準のみなら不要。独自暗号を入れたら見直し |
| デジタルサービス法 | 個人開発・トレーダー該当の実態に合わせる。有料化や EU 配信の変更時に見直す |
| ベトナムゲームライセンス | ゲームでなければ該当なし |
| 規制対象の医療用デバイス | ヘルスケア／フィットネスカテゴリでは申告必須。診断・治療機能がなければ「医療機器として機能しない」 |
| App Store サーバ通知・共有シークレット | アプリ内購入がなければ設定しない |

## Appのプライバシー

| 項目 | 決め方 |
|------|--------|
| プライバシーポリシーURL | 公開中のポリシーURL。サポートURLと同じオリジンであることが多い |
| データ収集 | コードとポリシーから判断。端末内のみ・識別子や行動を送らないなら「データを収集しない」→「デベロッパはこのアプリからデータを収集しません」。位置情報・連絡先・利用状況などを外部送信するなら該当カテゴリを申告し、目的・リンケージを正直に書く |

## アプリのアクセシビリティ

| 項目 | 決め方 |
|------|--------|
| iPhone のサポート機能 | 検証した機能だけ「はい」でチェック。未検証（VoiceOver 未対応、固定フォント、Reduce Motion 未対応、色のみの区別、未計測コントラスト等）は申告しない。対応を入れて実機確認したら追加する。動画がなければキャプション・音声ガイドは該当なし |

## 価格および配信状況

| 項目 | 決め方 |
|------|--------|
| 価格表 | 既存または無料なら基準国と ¥0。有料化はリポジトリから読み取れなければユーザー確認 |
| 配信可否 | 対応言語・対象地域から決める。国内専用なら日本のみ、など |
| 予約注文 | 不要なら設定しない |
| 税金カテゴリ | 既定（App Store ソフトウェア）でよいことが多い |
| Apple シリコン搭載 Mac で利用可能 | GPS・モーション・専用ハードウェア前提など Mac で動かないならオフ。既定でオンのことがあるので必ず確認 |
| Apple Vision Pro で利用可能 | 同上 |
| 一括購入（VPP） | 既定でよいことが多い |

## TestFlight

| 項目 | 決め方 |
|------|--------|
| 内部テスト | 自分を内部テスターに追加し、審査前にリリース構成で主要機能を確認 |
| テスト情報（外部テスト時のみ） | 外部テストを行わないなら不要 |
| ベータ版App Reviewの情報 | 外部テストを行わないなら不要 |

## 審査で指摘されやすい点

- **Guideline 2.3.7（Accurate Metadata）**: スクリーンショットに価格への言及（「無料」「Completely free」「割引」など）を入れると却下される。価格に触れたいなら概要文に書く

## プロジェクト側への記録（推奨）

各アプリの metadata または専用メモに、提出のたびに次を追記すると次回の自律更新が楽になる。

| 日付 | バージョン | 内容 | 審査結果 |
|------|-----------|------|----------|
| （提出日） | （MARKETING + BUILD） | （ユーザー向け変更の要約） | （通過／却下／未提出） |
