# PR Review

`gh pr view <PR番号またはURL>` と `gh pr diff <PR番号またはURL>` で目的と差分を確認し、必要な呼び出し元・テスト・設定を読む。番号だけの場合は現在のリポジトリを使う。

- PR が導入する不具合・回帰・セキュリティ上の問題を優先し、発生条件と影響をコードから確かめる。
- 命名の好みや依頼外のリファクタリングを、修正必須の問題として扱わない。
- 指摘ごとに重要度、ファイルと行、発生条件、影響、修正の方向を簡潔に示す。未確認の懸念は確定した不具合と区別する。
- 問題が見つからなければ、その旨と検証上の制約を伝える。件数を埋めるための指摘や「良い点」「総評」は不要。

レビュー依頼だけではコードの修正や GitHub へのコメント投稿・承認・マージを行わない。投稿も依頼された場合は、その範囲で実施する。
